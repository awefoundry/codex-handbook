# Codex 装不上、登不进、一直 loading 怎么办（2026-11 更新）：安装脚本、登录方式、证书与日志排查

> 本文在线版：[codexguide.io/guides/codex-install-login-troubleshooting](https://codexguide.io/guides/codex-install-login-troubleshooting)

> 核对依据：2026-11-09 的 [Authentication](https://learn.chatgpt.com/docs/auth)、[openai/codex README](https://github.com/openai/codex/blob/main/README.md)、[Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox)，以及 [rust-v0.162.0](https://github.com/openai/codex/releases/tag/rust-v0.162.0)（发布于 `2026-10-08T18:55:59Z`）和 [rust-v0.167.0](https://github.com/openai/codex/releases/tag/rust-v0.167.0)（发布于 `2026-11-06T01:40:00Z`）。当天 `npm view @openai/codex version` 为 `0.167.0`。Linux 上安装该版本后，`codex --version` 输出 `codex-cli 0.167.0`。`install.sh` 只下载阅读。没有 Windows，没有桌面应用，没有完成登录，没有新的截图。旧文里 CLI 0.146.1 和 VS Code 的配图已从本文移除。

登录的正常步骤见 [登录 Codex（2026-11 更新）：ChatGPT 账号、API Key、Sign in another way 与凭据存储方式](./07-登录Codex.md)。Windows 上怎么安装 CLI，见 [Windows 和 WSL 安装 Codex CLI（2026-11 更新）：签名 PowerShell 安装脚本、npm 与 WSL2 怎么选](./05-Windows和WSL安装Codex-CLI.md)。本文从「命令已执行，结果仍然不对」开始。

## 先确认是哪一个 Codex

常见入口有四个：ChatGPT 桌面应用、Codex CLI、VS Code 或兼容编辑器里的扩展，以及 JetBrains AI Assistant 里的 Codex。桌面应用的安装见 [Windows 安装 Codex App](./03-Windows安装Codex-App.md)、[macOS 安装 Codex App](./02-macOS安装Codex-App.md) 和 [Linux 安装 Codex App](./17-Linux安装Codex-App-Ubuntu-Debian-Fedora与Arch.md)。扩展见 [VS Code、Cursor 和 Windsurf 安装 Codex](./06-VS-Code和兼容编辑器安装Codex.md)。JetBrains 见 [JetBrains 中使用 Codex](./11-JetBrains中使用Codex.md)。

CLI 还要分清 Windows PowerShell 和 WSL。两套环境的 PATH、安装目录和 `~/.codex` 默认各有一份。Windows 里能运行，不表示 WSL 里也已安装或已登录。

在出问题的那一个终端里看版本和路径。

PowerShell：

```powershell
codex --version
Get-Command codex -All | Select-Object CommandType, Name, Source
codex login status
```

macOS、Linux 或 WSL：

```bash
codex --version
command -v codex
codex login status
```

2026-11-09，在 Linux 的独立 `CODEX_HOME` 里，未登录时 `codex login status` 输出 `Not logged in`，退出码为 1。这次还打印了一行警告：`CODEX_HOME` 在临时目录下时，它拒绝创建 PATH 辅助程序。那是隔离目录带来的，不是登录失败的原因。

## 先跑 codex doctor

安装、配置、登录和网络的检查项集中在 `codex doctor`。各行的含义、`--summary` 和 `--json` 见 [Codex doctor 自检](../15-故障排查与常见问题/04-Codex-doctor自检-安装配置登录与网络排查.md)。

0.167.0 的 `codex doctor --help` 包含 `--json`、`--network-only`、`--summary`、`--all`、`--no-color` 和 `--ascii`。当天在未登录的独立目录里，`--summary --ascii` 的 auth 行是失败，提示运行 `codex login` 或通过受支持的环境变量提供 API key。同一份输出里还有一条 websocket 警告，同时 HTTP 可达性是通过的。websocket 那一行只说明这台机器当时的网络，不要把它抄成所有人的故障。分享报告前去掉本机路径。

doctor 已经指出缺登录时，按下一节处理，不必先重装。

## 安装脚本、下载源和「找不到 codex」

README 当天的 Windows 命令是：

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"
```

`ByPass` 的大小写与 README 原文一致。`irm` 在 CMD 里不会被识别。窗口提示符应是 PowerShell 的 `PS`。0.162.0 的发布说明写 “Publish a signed PowerShell installer with Windows releases”。签名是否被本机信任，要在 Windows 上对下载后的脚本看 `Get-AuthenticodeSignature`。本文没有这项输出，也没有执行 `install.ps1`。

README 写：安装器默认从 `https://releases.openai.com/codex` 下载，元数据或安装包失败时回退到 GitHub Releases。把 `CODEX_INSTALLER_USE_RELEASES_OPENAI_COM` 设为 `false`（`0` 和 `no` 同样接受）则强制走 GitHub。2026-11-09 阅读的 `install.sh` 与此一致：未设置该变量时默认偏好 releases.openai.com；取值 `1`、`true`、`yes` 时仍走这一路；走不通时打印 `releases.openai.com is unavailable; falling back to GitHub Releases.` 本文没有执行 `install.sh`，没有看到这句警告在真实下载失败时出现。

npm 的对应命令是 `npm install -g @openai/codex`。本文用项目本地安装核对了 0.167.0，没有做全局安装。脚本安装和 npm 安装可能同时留在 PATH 里。更新之后版本不变时，用上一节的 `Get-Command` 或 `command -v` 看实际执行的是哪一个文件，再沿原来的渠道更新。更新和卸载见 [Codex 更新与卸载](./12-Codex更新与卸载.md)。

关掉安装时使用的终端，新开一个再查。旧窗口往往还拿着安装前的 PATH。Windows 与 WSL 要分别安装、分别查看。

## 浏览器登录成功，客户端仍未登录

Authentication 页写：ChatGPT 登录会打开浏览器，完成后凭据回到原来的客户端。回到发起登录的那个窗口，不要反复打开新的登录页，也不要复制地址栏里的回调参数。

CLI 在原终端等待之后，另开一个同一环境的终端：

```bash
codex login status
```

仍未登录时，按这个顺序：

1. 检查状态的终端必须和发起登录的是同一套环境。Windows 原生目录和 WSL 的家目录默认不共享。
2. 完全退出应用、IDE 或 CLI 后再开。
3. 看 `codex login --help` 里有没有 `--device-auth`。
4. 远程或无图形界面、或者本机网络挡住回调时，用设备码。前提写在 Authentication 页：先在个人账号的 ChatGPT 安全设置，或工作区权限里，打开设备码登录。然后在交互界面选 **Sign in with Device Code**，或运行 `codex login --device-auth`。

0.167.0 的帮助里有 `--device-auth`，说明文字是空的。步骤以 Authentication 页为准。本文没有走设备码，也没有浏览器回调。

同一页写：直接运行 `codex login` 时，会在配置的日志目录里写 `codex-login.log`，用来排查浏览器登录和设备码失败。本文没有生成这个文件。拿到日志后先去掉令牌、邮箱和回调地址，再考虑发给别人。

设备码不可用时，Authentication 页还有两条退路：在有浏览器的机器上登录后复制 `auth.json`，或用 SSH 转发本机 `localhost:1455`。凭据若在系统钥匙串里，复制 `auth.json` 不适用。把这个文件当作密码。具体命令以 Authentication 页和登录文为准，本文不重复粘贴。

## Sign in another way 和 API Key

0.167.0 发布说明写：API Key 和云厂商选项放在 “Sign in another way” 下面。Authentication 页的桌面应用步骤是：未登录屏幕选择 **Sign in another way**，输入密钥，再选 Continue。IDE 扩展的用词是 **Use API Key**，然后 OK。CLI 从标准输入读取：

```bash
printenv OPENAI_API_KEY | codex login --with-api-key
```

0.167.0 的帮助包含 `--with-api-key`，示例与此相同。不要把密钥写进命令行历史或截图。

API Key 按 OpenAI Platform 的价格计费，可以做本地流程。依赖 ChatGPT 工作区或云服务的功能会受限或不可用。Codex Cloud 需要 ChatGPT 登录。需要 Cloud 时，退出后再用 ChatGPT 账号登录，而不是反复更换 API Key。

```bash
codex logout
codex login
```

0.167.0 的帮助还包含 `--with-access-token`。那是 Enterprise 访问令牌，不是 API Key。本文没有令牌，没有执行这条命令。

## 一直 loading

CLI 能启动，只说明程序可以执行。模型若停在 loading，先看同一环境的 `codex login status`，再看 `codex doctor`。登录正常时，继续看代理和证书。本文没有复现 loading 画面，旧截图里的 0.146.1 界面已删除，不能当作当前 TUI 的样子。

## 代理和公司证书

`npm config set proxy` 只影响 npm。已经装好的 `codex` 另看当前终端的 `HTTP_PROXY` 和 `HTTPS_PROXY`。WSL 里的 `127.0.0.1` 不一定能访问只监听 Windows 的代理端口。

公司网络做 TLS 检查时，Authentication 页写：登录前把 `CODEX_CA_CERTIFICATE` 指到 PEM 包；未设置时回退到 `SSL_CERT_FILE`。同一组设置用于登录、普通 HTTPS 和安全 WebSocket。

```bash
export CODEX_CA_CERTIFICATE=/path/to/corporate-root-ca.pem
codex login
```

证书向公司 IT 索取。不要从论坛下载陌生证书，也不要关闭证书校验。本文没有私有根证书，没有看到这条变量改变登录结果。

## 扩展装上了，面板却没有反应

先核对扩展标识符 `openai.chatgpt` 和发布者，见 [IDE 扩展安全自查](../10-配置模型与权限安全/19-Codex-IDE扩展安全自查-确认官方openai.chatgpt与扩展投毒防范.md)。入口和登录按钮见 [VS Code、Cursor 和 Windsurf 安装 Codex](./06-VS-Code和兼容编辑器安装Codex.md)。

[Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox) 写：IDE 扩展已安装但没有响应时，系统可能缺少 C++ 开发工具，包括 Visual Studio Build Tools 的 C++ workload 和 Microsoft Visual C++ Redistributable（x64）。文档给出的命令是：

```powershell
winget install --id Microsoft.VisualStudio.2022.BuildTools -e
```

装完后完全重启 VS Code。本文没有 Windows，没有执行这条命令，也没有空白面板的新截图。公司电脑要遵守本机的软件安装策略。

## Windows 沙箱初始化失败

沙箱错误和扩展加载失败不是同一类问题。MXC、`elevated`、`unelevated` 和官方验证命令见 [Codex Windows 沙箱](../10-配置模型与权限安全/09-Codex-Windows沙箱-启用MXC与elevated-unelevated回退.md)。本文没有 Windows 11，没有复现错误 1385。不要把 `CODEX_HOME/.sandbox-secrets/` 的内容发给别人。日志里的令牌、用户名和项目路径也先去掉。

## 提交问题前收集这些

```bash
codex --version
command -v codex
codex login status
codex doctor
```

Windows 把 `command -v` 换成 `Get-Command codex -All`。另外记下：操作系统或 WSL 发行版、入口是应用、CLI、VS Code 还是 JetBrains、安装方式、登录方式是 ChatGPT、API Key 还是访问令牌、完整错误文字。浏览器登录或设备码失败时，再加上 `codex-login.log` 里去掉秘密之后的相关行。

不要上传整个 `.codex` 目录，不要分享 `auth.json`、Cookie、回调地址或 `.sandbox-secrets`。

## 快速检查

- [ ] 确认问题发生在应用、CLI、IDE 还是 JetBrains，并且 Windows 与 WSL 没有混用。
- [ ] 看了实际执行的 `codex` 路径，而不只看安装脚本的成功提示。
- [ ] 跑过 `codex doctor`，并按 auth 那一行决定要不要登录。
- [ ] 浏览器授权后回到了原来的窗口；需要设备码时，先在安全设置或工作区权限里打开。
- [ ] 分清了 ChatGPT 登录、API Key 和 Cloud。
- [ ] 代理和 `CODEX_CA_CERTIFICATE` 查过之后，才考虑重装。
- [ ] 分享的日志里没有账号、令牌、用户名和项目路径。
