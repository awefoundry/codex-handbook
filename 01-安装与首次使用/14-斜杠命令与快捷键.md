# Codex CLI 斜杠命令与快捷键：补上 0.171 的 /rc 与 /remote 配对码、输入框撤销重做和 MCP 状态栏，按用途分组速查

> 本文在线版：[codexguide.io/guides/codex-cli-slash-commands](https://codexguide.io/guides/codex-cli-slash-commands)

> 核对依据：2026-11-20 打开的 [Developer commands](https://learn.chatgpt.com/docs/developer-commands)，GitHub Release [rust-v0.171.0](https://github.com/openai/codex/releases/tag/rust-v0.171.0)，以及 PR [#61954](https://github.com/openai/codex/pull/61954) 对撤销重做默认键的说明。[CLI customization](https://learn.chatgpt.com/docs/cli-customization) 当天没有列出撤销重做的默认键，只把交互键位指回命令文档。Linux 上的 `codex-cli 0.171.0` 核对了 `codex --version` 和空配置下的 `features list`。没有打开交互式 TUI，没有看到命令菜单。
>
> 2026-11-20 更新：命令表改按当天的 Developer commands 重排。0.165.0 源码里的「任务运行中能不能用」和侧边对话允许列表没有在 0.171.0 上逐条重核，正文不再沿用那两份旧清单。

## 怎么用这张表

- 在输入框里输入 `/`，弹出命令菜单；继续输入命令名可以过滤。
- 有些命令后面可以直接带参数。Developer commands 的例子是 `/side Check whether this plan has an obvious risk`。`/clear` 的说明是清屏并开始一条新对话，当天这一节没有写它可以再带一个名字。
- **任务正在运行时**：输入斜杠命令后按 `Tab`，命令排进下一轮。官方写明，排队的命令在执行时才解析，所以菜单和报错会在当前这轮结束后才出现；排队前补全仍然可用。
- 同一页在「进行中的会话里用来调整」的例子里点了名：`/model`、`/fast`、`/permissions`、`/approve`、`/raw`、`/agents`、`/subagents`、`/status`。它没有再给每一条命令标「运行中可用」或「运行中不可用」。以前按 0.165.0 源码 `available_during_task` 画的 ✅／❌，这次删掉，避免把旧源码写成 0.171.0 的行为。
- 本文的分组是为了查找。命令是否出现在你的菜单里，还取决于版本、系统和账号。以输入框里的候选为准。

命令行里的子命令和启动参数（`codex exec`、`codex resume`、`--model` 等）不是斜杠命令，见 [Codex CLI 命令速查](../16-图解与速查/01-Codex-CLI命令速查-子命令与启动参数.md)。0.171.0 改了哪些默认行为，见 [Codex CLI 0.171.0](../12-官方工具与集成/30-Codex-CLI-0.171-默认GPT-6.2-Sol-终端工作区默认开启与exec-remote.md)。

## 会话与模型

### 模型、权限与审批

| 命令 | 作用 |
| --- | --- |
| `/model` | 选择当前模型；有推理强度时一起选。命令页写：工作区有权限的话，日常编码可以选择 GPT-6.2 Sol |
| `/fast` | 打开或关闭当前模型的 Fast 服务档位。只有模型目录提供了这个档位才会出现 |
| `/permissions` | 调整 Codex 不问你就能做什么，例如在 Auto 和 Read Only 之间切换 |
| `/approve` | 自动审查拒绝了某个操作时，批准重试一次 |
| `/plan` | 切到计划模式，可以直接带上要求 |
| `/goal` | 设置、修改、暂停、恢复、查看或清除任务目标 |
| `/daybreak` | 账号和模型符合条件时，打开或关闭 Daybreak |

0.171.0 的 Release 把 GPT-6.2 Sol 写成模型目录的默认选择。这和 `/model` 里「可以选择 Sol」是两句不同的话。套餐和企业开关见 [GPT-6.2 Astra 与 Sol](../10-配置模型与权限安全/29-Codex使用GPT-6.2-Astra与Sol-怎么选-切换方法-Ultrafast与额度.md)。`/goal` 的用法见 [Codex Goal 模式](../11-自动化与高级工作流/08-Codex使用Goal模式运行长任务.md)。

空配置、未登录时，2026-11-20 的 `codex exec` 启动摘要在请求失败前打印了 `model: gpt-6.2-sol`。本文没有打开 `/model` 菜单，不能描述菜单上的光标停在哪一项。

### 会话管理

| 命令 | 作用 |
| --- | --- |
| `/new` | 在同一个 CLI 里开始一条新对话 |
| `/clear` | 清屏并开始一条新对话 |
| `/resume` | 从会话列表里恢复之前的对话 |
| `/fork` | 把当前对话分叉成一条新对话 |
| `/side`（别名 `/btw`） | 开一个侧边对话，转录不进主对话 |
| `/rename` | 给当前对话改名 |
| `/archive` | 归档当前会话，从活动列表里移走，不删记录 |
| `/delete` | 永久删除当前会话及其后代会话 |
| `/agents` | 打开 Agent 指挥中心，浏览对话、切换 Agent |
| `/subagents` | 切换到某个子 Agent 的线程 |
| `/app` | 把当前会话转到 ChatGPT 桌面端继续。命令页写这是 macOS 和 Windows |
| `/quit`、`/exit` | 退出 CLI |

`/side` 默认是临时的。命令页写：本地全屏会话里如果已经打开 `features.tui_workspace`，并且有已保存的历史，`/side` 会重新打开已有的 side chat，后面带上文字会新开一条；重启后可以从侧栏再打开已保存的 side chat。在另一条 side chat 里，以及 review 模式中，`/side` 不可用。工作区从 0.171.0 起默认开启，见 [终端工作区](../12-官方工具与集成/27-Codex终端工作区-并排side-chat多标签页与重启后恢复.md)。

多条对话怎么恢复和交接，见 [管理多条任务线](../11-自动化与高级工作流/03-CodexCLI管理多条任务线.md)。

## 远程：/rc、/remote 与设备配对码

0.171.0 Release 的原文是：

> Added `/rc` and `/remote` to manage local remote control and display device pairing codes from the TUI. (#62121)

提交标题是 “Add `/rc` to manage remote control from the TUI”。

2026-11-20 的 Developer commands 斜杠命令表里没有 `/rc`，也没有 `/remote`。因此本文只保留这句：在 TUI 里管理本机远程控制，并显示设备配对码。不写菜单层级、码的长度或它出现在屏幕的哪一块。本文没有打开 TUI，没有看到配对码。

手机或另一台电脑控制已配对主机，是另一条路径，步骤在 [远程连接](../12-官方工具与集成/01-Codex远程控制另一台Mac.md)。`codex --remote` 接到你自己启动的 app server，见 [远程终端](../12-官方工具与集成/31-Codex远程终端-app-server-listen与codex-remote连接.md)。不要把这三条当成同一个命令。

## 界面：/statusline 与实验性的 MCP 状态栏

官方命令页对 `/statusline` 的说明是：交互式选择和排列底部状态栏。可选项目包括模型、模型加推理强度、上下文、额度、Git 分支、token 计数、会话 id、当前目录或项目根，以及 Codex 版本。确认之后写入 `config.toml` 的 `tui.status_line`。只想改这一次会话，可以按显示顺序写出项目名，例如 `/statusline model project-name`；`/statusline --clear` 会在这次会话里隐藏全部项目。

0.171.0 Release 在此之外加了一句：

> Added custom MCP status line selection and authoring through `/statusline` when `tui_extensions_statusline` is enabled. (#61979, #61988, #62037)

也就是：只有打开 `tui_extensions_statusline` 之后，才用 `/statusline` 选择和编写自定义 MCP 状态栏。2026-11-20、空配置、未登录时，`codex features list` 里这个开关的 stage 是 `experimental`，有效状态是 `false`。当天的命令页没有写 MCP 状态栏的步骤。本文没有打开这个开关，没有编写过 MCP 状态栏。

同一组界面命令还有：

| 命令 | 作用 |
| --- | --- |
| `/title` | 选择终端窗口或标签页标题显示的内容，写入 `tui.terminal_title` |
| `/theme` | 选择语法高亮主题，写入 `tui.theme` |
| `/pets`、`/pet` | 选择或隐藏终端宠物。`/pets off` 会隐藏 |
| `/tui` | 选择下次启动时的终端模式：保留滚动记录，或全屏转录 |
| `/raw` | 切换原始滚动模式，方便选中复制长输出 |
| `/keymap` | 查看、修改并保存 TUI 快捷键到 `config.toml` 的 `tui.keymap` |
| `/vim` | 打开或关闭输入框的 Vim 模式 |
| `/experimental` | 开关实验功能。命令页的例子包括网络代理，以及运行时防止休眠 |
| `/setup-default-sandbox` | 设置提权的 Windows 沙箱。命令页写这是 Windows |

主题、状态栏和改键的配置键见 [终端界面设置](../16-图解与速查/03-Codex-CLI终端界面设置速查-主题补全编辑器状态栏与改键.md)。

## 输入框快捷键

### 命令页列出的键

以下来自 2026-11-20 Developer commands 的 Interactive shortcuts。当天这张表里没有 `Ctrl+L`。本文不再把 `Ctrl+L` 写成当前快捷键。`/clear` 仍是清屏并新开一条对话。

| 按键 | 作用 |
| --- | --- |
| `@` | 搜索工作区文件，把路径加进消息 |
| `↑` / `↓` | 翻出之前的草稿 |
| `Ctrl+R` | 搜索历史消息，`Enter` 选用，`Esc` 取消 |
| `Ctrl+O` | 复制最近一条已完成的回复 |
| 行首加 `!` | 按当前的审批和沙箱设置运行一条本地 shell 命令 |
| `Tab`（任务运行中） | 把消息、斜杠命令或 shell 命令排进下一轮 |
| `Enter`（任务运行中） | 把新指令插进当前这轮 |
| 输入框为空时按两次 `Esc` | 编辑上一条用户消息，并从那里分叉对话 |
| `Ctrl+C` | 关闭会话，同 `/exit` |

[CLI customization](https://learn.chatgpt.com/docs/cli-customization) 另外写了 `Ctrl+G`：在输入框里打开 `VISUAL` 或 `EDITOR` 指定的编辑器，用来写更长的提示。那一页没有写撤销和重做的默认键。

想改键用 `/keymap`。命令页写：选场景和动作，输入新绑定或删掉现有绑定；结果写入 `tui.keymap`。具体场景名以 `/keymap` 里看得到的为准，见 [终端界面设置](../16-图解与速查/03-Codex-CLI终端界面设置速查-主题补全编辑器状态栏与改键.md)。

### 撤销与重做

0.171.0 Release 的原文是：

> Added configurable undo and redo shortcuts to the non-Vim prompt composer, including restoration of attachments and large pastes. (#61954)

范围是非 Vim 的输入框，而且可配置。恢复的内容包括附件和大段粘贴。

默认键位以 PR [#61954](https://github.com/openai/codex/pull/61954) 的说明为准，不是命令页：

- 撤销：Unix 上 `Alt+Z`，Windows 上 `Ctrl+Z`，以及 `F7`；macOS 上还可以用 `Super+Z`
- 重做：在撤销键上加 `Shift`

同一段写，这些动作在快捷键选择器里的名字是 `composer.undo` 和 `composer.redo`。连续输入会并成一步，连续退格另成一步，检测到的大段粘贴和前面的输入分开。本文没有打开 TUI，没有按过这些键，也没有在 `config.toml` 里写过对应绑定。官方命令页和 CLI customization 页都没有重复这组默认键。若你屏幕上的键和 PR 说明不一致，以 `/keymap` 里当前绑定为准，不要同时试一套网上的第三种组合。

## 命令找不到时

1. 看版本：`codex --version`。本文按 0.171.0 的 Release 和当天的命令页核对。
2. 更新方法见 [Codex 更新与卸载](./12-Codex更新与卸载.md)。要钉住 0.171.0，用带版本号的 npm 命令，见 [0.171.0 一文](../12-官方工具与集成/30-Codex-CLI-0.171-默认GPT-6.2-Sol-终端工作区默认开启与exec-remote.md)。
3. 有条件的命令：`/fast` 要模型目录提供 Fast 档位；`/app` 的桌面端继续写的是 macOS 和 Windows；`/setup-default-sandbox` 是 Windows；`/daybreak` 和 `/voice` 取决于账号、模型和当前构建；`/rc`、`/remote` 官方命令表还没收录。
4. 任务正在跑时，先按 `Tab` 排队，不要把「没立刻执行」理解成命令已被删除。

## IDE 扩展里的命令

VS Code、Cursor、Windsurf 里的 Codex 扩展有自己的斜杠命令。2026-11-20 的 Developer commands 列出的是：

| 命令 | 作用 |
| --- | --- |
| `/approve` | 自动审查启用时，批准重试一次被拒绝的操作 |
| `/cloud` | 在云端运行这个对话（云端执行可用时） |
| `/cloud-environment` | 选择这个对话的云端环境 |
| `/compact` | 压缩当前对话的上下文 |
| `/fast` | 开关 Fast 服务档位（可用时） |
| `/feedback` | 打开反馈窗口，可以附带日志 |
| `/fork` | 把本地对话复制成一条新的本地对话 |
| `/goal` | 设置一个让 Codex 持续追踪的目标 |
| `/ide-context` | 开关自动附带 IDE 上下文 |
| `/init` | 为当前项目生成 `AGENTS.md` 骨架 |
| `/local` | 在本地工作区运行这个对话 |
| `/mcp` | 打开 MCP 状态，查看已连接的服务器 |
| `/memories` | 设置对话是否使用或生成记忆（可用时） |
| `/model` | 选择当前对话的模型 |
| `/plan` | 开关计划模式 |
| `/project` | 选择新对话所在的项目 |
| `/reasoning` | 选择当前对话的推理强度 |
| `/review` | 进入代码审查模式，审查未提交的改动或和基准分支对比 |
| `/side` | 开一个临时侧边对话，不打断主对话 |
| `/status` | 显示对话 ID、上下文用量和额度 |
| `/worktree` | 在新的 Git worktree 里运行这个对话 |

当天这张表里没有 `/personality`，也没有 CLI 的 `/statusline`、`/keymap`、`/rc`、`/remote`。
