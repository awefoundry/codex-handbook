# 第 3 课：Codex 打开第一个本地项目，在 App、CLI 或 IDE 里选对练习目录，用一条只读提示确认两个文件

> 本文在线版：[codexguide.io/guides/da-kai-di-yi-ge-ben-di-xiang-mu](https://codexguide.io/guides/da-kai-di-yi-ge-ben-di-xiang-mu)

> 核对依据：2026-11-22 的 [ChatGPT desktop app](https://learn.chatgpt.com/docs/app)、[Codex CLI](https://learn.chatgpt.com/docs/cli) 入门，以及 [Permissions](https://learn.chatgpt.com/docs/permissions) 里对 `read-only` 的说明。CLI 帮助来自 Linux 上的 `codex-cli 0.171.0`：`codex exec --help` 列出 `--sandbox` 的 `read-only`、`workspace-write`、`danger-full-access`，以及 `--trust` 和 `--skip-git-repo-check`。练习包 `Codex首次任务-本地网页练习包.zip` 里的 `起始文件/index.html` 在仓库中读过，预期句子以这份文件为准。没有桌面应用，没有 IDE，没有打开交互式 Codex，没有配新的截图。

本课接在 [第 2 课：登录 Codex](./07-登录Codex.md) 之后。你已经选好 App、CLI 或 IDE 里的一个入口，并且登录完成。这一课只做一件事：把**复制出来**的练习目录交给那个入口，用一条只读提示确认两个文件。改标题和简介是 [第 4 课：完成第一次网页修改](../00-从这里开始/07-完成第一个真实任务.md)。

## 1. 取得并复制练习包

如果你已在前面的课复制了 `codex-first-task-test/`，直接沿用它，不要再复制一份。还没有这份目录时，下载[本地网页练习包](../练习材料/Codex首次任务-本地网页练习包.zip)，解压后找到 `起始文件/`，把它复制到新的测试目录，例如：

```text
codex-first-task-test/
├── index.html
└── styles.css
```

外层练习包还有任务说明、检查清单和参考差异。它们帮你了解材料。真正交给 Codex 打开的工作目录，就是上面这两个文件。不要直接修改原始 `起始文件/`。

2026-11-22 读到的 `起始文件/index.html` 里，主标题是「晨间读书角」，简介是「用十分钟记录今天读到的一段话，慢慢建立自己的阅读清单。」，按钮文字是「查看阅读清单」，链接是 `https://example.com`。`styles.css` 由这个 HTML 用 `<link rel="stylesheet" href="styles.css">` 引入。本课不要求 `README.md`、`package.json`、`src/`、`tests/`、Git 仓库或 Node.js。

## 2. 在你选定的入口打开这个目录

先在系统文件管理器里打开副本，确认这一层**直接**有 `index.html` 和 `styles.css`。打开了外层的 `首次任务-本地网页/`，或打开了单个 HTML 文件，都不算打开项目。

### 桌面应用

[ChatGPT desktop app](https://learn.chatgpt.com/docs/app) 的开始步骤是：安装、登录，然后选择在哪里工作。原文是 start a chat, create a project, or **open a folder**。它接着写：ChatGPT 可以使用你选的位置里的文件和上下文。下一步是发送第一条消息，并在 Codex 里从 New chat 开始。

文档没有写出「打开文件夹」对应的按钮名字，也没有写出中文界面的菜单路径。在桌面应用里打开文件夹或选择项目位置，具体按钮以当前界面为准。选中 `codex-first-task-test/` 之后，再回到文件管理器核对那两个文件名。本文没有桌面应用，没有截图。

不要把 Cloud 当作这一课的入口。练习文件在你电脑上，Cloud 任务不会自动看见这个未上传的本地目录。

### Codex CLI

[Codex CLI](https://learn.chatgpt.com/docs/cli) 的入门写：打开项目目录，运行 `codex`。第一次运行时选择 **Sign in with ChatGPT** 或其他可用的登录方式。登录已经在第 2 课完成，这里不要换一种登录。

下面的路径是例子，换成你电脑上的真实路径。路径里有空格时保留引号。macOS 和 Linux：

```bash
cd "/你的实际路径/codex-first-task-test"
pwd
ls
codex
```

Windows PowerShell：

```powershell
Set-Location "C:\你的实际路径\codex-first-task-test"
Get-Location
Get-ChildItem
codex
```

`pwd` 或 `Get-Location` 的最后一层应是 `codex-first-task-test`。列出的名字里应直接有 `index.html` 和 `styles.css`。出现「找不到路径」时，先改路径，不要继续运行 `codex`。

官方入门页没有逐步写出「第一次进入这个目录」时的信任对话框。本文没有交互式终端，没有看到那个对话框，所以不写按钮名。0.171.0 上能核对的是 `codex exec` 的帮助，见下一节。

### IDE 扩展

在编辑器里打开 `codex-first-task-test/` 这个文件夹，再打开 Codex 侧栏。VS Code 里从文件菜单打开文件夹的旧截图，在 [VS Code 和兼容编辑器安装 Codex](./06-VS-Code和兼容编辑器安装Codex.md)。那张图的菜单文字是当时界面上的「打开文件夹」。本课不要求为了练习另外安装 VS Code。扩展认的是编辑器当前打开的文件夹，不是某一个已经打开的标签页。侧栏里看不到项目文件时，先确认打开的是文件夹，而不是单个文件。那篇安装文写了这个检查。

## 3. 第一次进入目录：信任和只读

这一课的提示只读两个文件，不写盘。权限上的对应档是只读。

[Permissions](https://learn.chatgpt.com/docs/permissions) 把沙箱和审批分开。本站 [权限沙箱与审批](../02-核心概念与任务方法/06-权限沙箱与审批-什么时候放行什么时候收紧.md) 写：只想看、不动文件时用 `read-only`。2026-11-22 的 `codex exec --help` 里，`--sandbox` 的可选值是 `read-only`、`workspace-write`、`danger-full-access`。

交互会话里，官方 CLI 页写可以用 `/permissions` 查看当前沙箱和可写根。本文没有打开会话，没有看到 `/permissions` 的菜单。发下面那条提示之前，如果界面上的权限不是只读，先改到只读再发。不要为了这一课改成可写或完全访问。

**`--trust` 不是这一课的步骤。** 0.169.0 起，未信任目录里的 `codex exec` 和 `codex review` 不加载项目级配置和项目 MCP。0.171.0 的帮助仍是：

```text
--trust
Save trust for this project and future chats, including MCP commands outside the sandbox.
Persists even with --ephemeral. Does not override an explicitly untrusted project
```

练习目录没有 `.codex/config.toml`，也没有项目 MCP。加上 `--trust` 不会帮助你核对那两个文件，还会把信任记进配置。什么时候才需要它，见 [Codex 自动化与 CI](../11-自动化与高级工作流/07-Codex自动化与定时任务-从手动流程到稳定执行.md)。

练习目录也不是 Git 仓库。自动化一文在 0.169.0 上记录过：非 Git 目录里的 `codex exec` 会拒绝，并提到 `--skip-git-repo-check`。0.171.0 的 `codex exec --help` 仍有这个旗标。本文没有在练习目录里重跑 `codex exec`，也没有看到交互式 `codex` 对非 Git 目录是否同样拒绝。官方入门页只写打开项目目录后运行 `codex`。交互式如果停住，先看它的原文，不要为了这一课去 `git init`。

## 4. 发一条只读提示

在 Codex 输入框发送：

```text
请先只读取当前目录的 index.html 和 styles.css，不修改文件。
告诉我：当前主标题、简介、按钮文字和链接地址分别是什么。
如果缺少任何一个文件，先说明当前目录里有哪些文件，不要创建文件补齐。
不要安装依赖、构建或部署。
```

Codex 应该能指出：

- 当前主标题是「晨间读书角」；
- 简介是「用十分钟记录今天读到的一段话，慢慢建立自己的阅读清单。」；
- 按钮文字是「查看阅读清单」；
- 链接地址是 `https://example.com`；
- `styles.css` 是当前页面的样式文件。

这些句子来自练习包当前的 `起始文件/index.html`。输出不同时先停止，不要创建文件，也不要开始改字。

本文没有登录，没有把这条提示发给模型，所以上面是对照源文件应有的答案，不是一次实测的模型回复。

## 5. 文件找不到或输出不一致时

按这个顺序查，查完再重发那条只读提示：

1. 看 Codex 报告的当前目录文件列表，或你自己在终端里的 `ls` / `Get-ChildItem`。这一层必须同时有 `index.html` 和 `styles.css`。
2. 不要让 Codex 创建缺少的文件来「补齐」。缺文件说明打开的位置不对。
3. 不要把桌面、练习包外层、`参考差异/` 或另一个项目当成工作目录。
4. 主标题不是「晨间读书角」时，多半用了改过的旧副本。从原始 `起始文件/` 再复制一份，仍不要改原始文件。
5. 桌面应用、CLI 和 IDE 不要各开一个不同的目录。第 4 课继续用这一份 `codex-first-task-test/`。

本课程不把 `README.md`、`package.json` 或 Git 仓库写成前提。那些文件出现在别的项目里是正常的，不能用来判断这次练习「还没准备好」。

## 完成检查与下一课

- [ ] 当前工作目录直接包含 `index.html` 和 `styles.css`。
- [ ] 用的是原始起点的复制品，没有改原始 `起始文件/`。
- [ ] 这一轮是只读核对，没有创建文件、安装依赖或部署。
- [ ] 读到的主标题是「晨间读书角」，链接是 `https://example.com`。
- [ ] 知道下一课只改 `index.html` 里的两处文字，目录不再换。
