# Mac mini computer-use 补拍 prompt（第 05 篇配图）

> 用法：把下面"任务 Prompt"整段粘贴给 Mac mini 上的 computer-use agent。拍完后把 7 张 PNG 拷回本文工作区，替换正文中对应的官方截图或作为补充证据。

## 任务 Prompt（直接粘贴）

```
你在一台 Mac mini 上操作 macOS。任务：为一篇 Codex 安全教程补拍 7 张界面截图。

【硬性安全规则——任何一条违反就立即停止并报告】
1. 所有操作只在一次性测试目录 ~/codex-screenshot-demo/ 里进行。先创建它：
   mkdir -p ~/codex-screenshot-demo && cd ~/codex-screenshot-demo && git init
   禁止打开、修改、删除用户主目录下任何其他文件夹、真实项目或生产数据。
2. 遇到"批准/Allow/确认"按钮时，停在点击之前截图，截图后一律按 Esc 或选拒绝，不实际执行高风险命令。
3. 不截图、不录入：账号、邮箱、组织名、API Key、Token、Cookie、登录二维码、
   手机号、付款信息、真实工作区路径。终端里如出现，先清屏或用测试数据覆盖再截。
4. 不故意提交可能违反使用政策的内容（第 6 张图有特殊说明，见下）。
5. 截图只保留目标窗口本身（用 Cmd+Shift+4 再按空格点选窗口），不要截整个桌面、
   不要带入 Dock 通知、私人标签页或其他窗口。

【输出要求】
- 全部保存为 PNG，放到 ~/codex-screenshot-demo/shots/，文件名严格如下：
  01-permission-mode-selector.png
  02-approval-prompt-before-command.png
  03-git-diff-review.png
  04-focused-test-result.png
  05-risk-checklist.png
  06-policy-warning-new-session.png
  07-delete-target-review.png
- 每张拍完立即用 Quick Look 打开确认文字清晰、无敏感信息，不合格当场重拍。
- 最后输出一份清单：每张图是否拍到、画面里证明了什么、哪张没拍到及原因。

【第 1 张：权限模式选择器】
打开 Codex（CLI 或桌面端均可，优先桌面端界面更直观），进入权限/Permissions 设置，
展开审批模式和沙箱模式的可选项。画面要同时看到"当前模式"和"其他可选模式"，
证明权限不是单纯的开/关。停在"应用/确认"之前截图。

【第 2 张：命令批准提示】
在 ~/codex-screenshot-demo/ 里启动一个 Codex 会话，给它一个会修改文件的小任务
（例如"创建一个 hello.txt 并写入一行字"）。当 Codex 弹出批准提示、显示将要执行的
命令和目标路径时截图。画面必须包含：完整命令、目标范围、批准/拒绝按钮。
停在批准按钮之前，截完拒绝该命令。

【第 3 张：git diff 复核】
在 ~/codex-screenshot-demo/ 里手动改动两三个文件（内容随意，用测试文本），
终端依次运行：
  git add -A && git commit -m init（先有一个基线提交）
  改文件后：git diff --stat
  再运行：git diff
截取同时能看到 --stat 摘要和具体差异的终端画面。证明"测试之外还要看实际差异"。

【第 4 张：聚焦测试结果】
在测试目录里放一个最小测试（例如一个 Python 文件加一个 pytest 用例，或 npm test），
终端运行该聚焦测试命令。截取包含"实际命令 + 通过/失败统计"的画面。
不执行任何发布、合并、推送操作。

【第 5 张：风险判断清单】
用文本编辑器打开一个 Markdown 文件，内容只放这张四问清单（从下文原样复制）：
  1. 它会接触什么：示例代码、个人文件、凭据、客户数据，还是生产资源？
  2. 能不能回退：有 Git、备份、事务或可丢弃环境吗？
  3. 怎么验证：有聚焦测试、构建、预览和人工复核吗？
  4. 出错会怎样：影响一个分支，还是会删除、发送、发布或改变云资源？
截取清单完整可见的画面，窗口里不要出现其他私人文件内容。

【第 6 张：政策警告 + 新会话（特殊：允许拍不到）】
不要故意构造或反复提交违规提示去触发警告，那会触发账号风控，与文章立场相反。
只在以下两种情况截图：
  a) 今天正常使用 Codex 时自然出现过"prompt was flagged / 违反使用政策"类提示；
  b) 此前已有留存的真实警告画面。
拍到警告后，停止提交，新建一个空白会话，截取"警告提示 + 空白新会话"同屏
（或警告与新建会话按钮同框）的画面，隐藏账号与网络信息。
如果没有自然出现的警告，这张标记为"未拍到"，直接跳过，不要伪造。

【第 7 张：删除前核对目标路径】
在 ~/codex-screenshot-demo/ 里建一个可丢弃子目录 tmp-cleanup/（里面放几个测试文件）。
在终端输入一条指向该目录的删除命令，例如：
  rm -rf ~/codex-screenshot-demo/tmp-cleanup
但不要按回车。调整终端让完整目标路径清晰可见，旁边另开一个终端窗口显示
git status 或 ls 结果作为"删除前核对"的对照。截取两个窗口同框画面后，
按 Ctrl+C 取消命令，禁止真正执行删除。
```

## 拍完之后（人工或下一轮 agent 做）

1. 把 `~/codex-screenshot-demo/shots/` 下的 PNG 拷回本工作区（本目录）。
2. 按 gzhwz/imagegzh 一号样式逐张处理：清理浏览器/滚动条残片，4 px 白边、10 px 圆角、1 px `#d9d9d9` 边框、轻阴影；不改动画面文字。
3. 对照 `manual-steps.md` 的验收点逐张勾选；`06` 允许空缺，空缺时在交付报告中写"未拍到 + 原因"，不伪造。
4. 原图留在本备份目录，处理图输出到文章目录并更新正文引用与 `gzhwz-processing-report.md` 映射。
