# Review 检查顺序配图提示词

Create a polished 16:9 explanatory editorial illustration for a Chinese software engineering article about high-quality Code Review. Show a clear left-to-right or top-to-bottom five-step review path: understand PR goal, confirm change scope, inspect correctness and security boundaries, compare test coverage, then write the review conclusion. Use simple abstract code-diff panels, a magnifying glass, boundary markers, test checkboxes, and a final review decision panel. The image should help readers understand the order of checks at a glance.

Use a bright white background with deep graphite text-like shapes, restrained low-saturation green and red accents, and a small amount of warm yellow. Keep the composition clean, balanced, and readable on a phone. Use only short, accurate labels if text is rendered: “目标”, “范围”, “正确性 / 安全”, “测试”, “结论”. Do not add any other words. If Chinese text cannot be rendered reliably, use numbered stages and clear icons instead of malformed text.

Do not use real GitHub UI, real logos, real URLs, usernames, repository names, file paths, API keys, tokens, QR codes, watermarks, people, or invented metrics. No cyberpunk, neon, purple gradients, decorative orbs, or dense fake interface copy. The result must be a content-specific conceptual diagram, not a generic tech background.
