# 封面生成提示词

## 标题
高质量 Code Review 怎么做？从正确性到测试的检查顺序

## 任务
为一篇面向中文开发者和使用 Codex 参与软件开发的读者的微信公众号文章生成一张横版封面。主题是高质量 Code Review，重点表现从理解 PR 目标、查看代码差异、识别正确性与安全风险、核对测试，到提交 Review 结论的审查过程。

## 画面方向
采用克制、清晰的数字编辑插画风格。画面主体放在右侧，包括抽象化的 Pull Request 变更界面、放大镜、代码差异行、测试检查标记和审查结论面板。界面只作为无品牌的概念视觉，不要复刻真实 GitHub 页面，不要加入任何真实品牌 Logo、网址、账号、仓库名、人物姓名、编号或二维码。让画面表达“看清范围、检查风险、用测试确认”的关系。

## 构图与文字安全区
画布固定为 2.35:1，940×400 px。标题放在左侧 40% 的安全区内，分成两到三行，字号足够大，在手机缩略图中仍清楚可读。右侧保留视觉主体，避免覆盖标题。四周保留安全边距，所有标题文字和主要对象都不能贴边或被裁切。只出现下面这一条中文标题，不要生成副标题、标签、按钮、说明文字或任何额外文字。

## 配色与质感
以白色和深石墨色为基础，使用 Git diff 常见的低饱和绿色与红色作为少量对比色，再加入一点暖黄色作为审查重点提示。整体明亮、专业、安静，避免紫色主导、霓虹、赛博朋克、复杂渐变、装饰性光球和过度阴影。使用清晰的平面数字绘制与轻微纸张纹理，保证文字和画面有高对比度。

## 硬性约束
- 必须准确呈现标题：高质量 Code Review 怎么做？从正确性到测试的检查顺序
- 只生成一张封面，比例 2.35:1，目标尺寸 940×400 px
- 不添加任何其他文字、Logo、品牌、真实网址、账号、路径、数字、人物身份、二维码或水印
- 不使用真实人物，不使用可识别的 GitHub 界面截图，不编造产品功能或文章事实
- 保持标题位于左侧安全区，主体位于右侧，画面简洁并适合公众号封面缩略图
