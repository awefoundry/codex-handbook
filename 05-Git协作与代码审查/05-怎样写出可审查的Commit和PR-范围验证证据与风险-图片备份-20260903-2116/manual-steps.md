# 需要作者亲自截图

本篇只需要本机终端和一个可安全查看的测试 PR 画面。请使用一次性示例分支或脱敏后的现有仓库，不要把真实客户数据、私有路径、令牌或账号信息放入终端。

## 终端证据

- [ ] `01-commit-pr-evidence-terminal.png`：起始位置为文章示例仓库的终端；依次运行 `git diff --stat`、`git diff --check`，必要时用 `git add -p` 选择一个独立改动，再运行 `git diff --cached --stat` 或 `git show --stat --oneline HEAD`；预期画面证明“提交范围可见、空白错误已检查、提交目的可追踪”；隐藏用户名、邮箱、私有路径、仓库地址、客户数据和令牌；停在 `git commit` 或提交摘要之后，不要执行推送、删除或强制覆盖。

## PR 页面证据

- [ ] `02-pr-description-scope-risk.png`：起始网址为已登录的 GitHub 测试仓库 PR 页面；菜单路径为 `Pull requests` → 选择测试 PR → `Conversation`；预期画面同时包含“改了什么、为什么改、如何验证、风险与回滚、待确认”字段，证明 PR 文本可审查；隐藏仓库名、组织名、评论者邮箱、内部链接、客户数据和令牌；停在提交评论、合并或关闭 PR 之前。

## 截图检查

- [ ] 文件使用上面的数字前缀，放入本工作区的 `manual/`。
- [ ] 图片宽度至少 1000 px，命令和 PR 字段清晰可读。
- [ ] 截图中没有登录二维码、Cookie、令牌、账号标识、私有路径或客户数据。
- [ ] 截图只证明当前文章步骤，不使用封面、缩略图、Logo 或装饰图。
